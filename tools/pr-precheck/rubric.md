# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| no unplanned changes | every file and hunk in the candidate pr's "diff", read against the plan's "files" line, its scope statement, and any deviation note. | pass if every changed file and hunk is work the plan names or its scope needs (the fix, its tests, its changelog or docs entry), or is a change the plan's deviation note or the description states and that the fix needs. fail if any hunk rewrites or restyles a function the plan never names, adds an option, flag, setting or api the plan scopes out or never mentions, or edits a file the plan does not name and no deviation note covers. a change that is disclosed but not needed to fix the issue (a cleanup, a rename, an adjacent feature) still fails. | required |
| claims match the diff | every sentence in the candidate pr's "description" that says what the pr does, adds, covers or leaves out ("exactly as planned", "no changes beyond the plan", "tests added", "docs updated", "no options added"), read against the "diff", and the plan's list of deliverables (code change, tests, docs, changelog). | pass if every claim is shown by a line in the diff, and every deliverable the plan lists is in the diff or is named as deferred in the plan's deviation note and restated in the description. an honest shortfall passes. fail if the description claims something the diff does not contain (a docs update, a test, "exactly as planned" over an unplanned hunk), or if a planned deliverable is missing from the diff and no note says so. a claim that something was not added passes when nothing in the diff adds it. | required |
| decisive before and after | the "test evidence" section, read against the plan's test plan and the repro evidence in "plan context". | pass if the evidence re-runs the plan's repro on the path that was broken (the issue's own input or steps, not a control), and shows the observable result before and after (printed output, an exit code, a value, or a quoted result) so the two differ the way the plan expected. fail if the only evidence is a statement ("tested locally", "works now", "verified on my machine"), if it exercises only a control or an unchanged path, or if it skips a failing step that the plan's test plan names and nothing says why. | required |
| repo checks shown | the "test evidence" section, read against the checks the plan's test plan names and the checks the "repo facts" section says the repo asks for (test suite, linter, type checker, formatter). | pass if each check the plan or the repo names as the test command is shown as run, with its command and its outcome (a pass count, an exit status, or its failure reported honestly with the reason). a formatter or linter named with its outcome (for example "fmt and clippy clean") or stated as a ticked checklist item counts as shown. fail if a named check is missing, if the only claim is "tests pass" with no command named, or if a failing check is hidden. | required |
| clean diff | the candidate pr's "diff" and "commits" list. | pass if the diff holds only the change itself and nothing that buries it. fail if the diff adds debug output (a print or log line left in), commented-out code, a dead or unused function, import, or variable, a leftover todo, whitespace or formatting-only churn, or a re-indented block with no logic change. an explanatory comment is not debris. a commit message such as "wip" never fails this check on its own. | required |
| template asks met | the "pull requests" line in "repo facts" (template sections, issue link, checklist, changelog entry, tests), read against the "description" and the "diff". | pass if each ask the repo states for a pr is done with real content: sections filled, the issue linked if asked, checklist items true, a changelog or release-notes entry in the diff if asked, tests in the diff if asked. an ask that does not apply may be marked n/a with a reason. a repo with no template and no stated asks passes. fail if a stated ask is visibly skipped or left as boilerplate. | required |
| ai disclosure | the "contribution policy" line in "repo facts", read against the "description". | pass if the policy does not require disclosing ai use in contributions generally (no ai policy, assistive use allowed, or a rule only about writing comments in your own words), or if the description contains an explicit statement that ai was used that names the tool or extent. fail if the policy says all ai use must be disclosed and the description has no such statement. | required |
| maintainer direction engaged | the "thread highlights" section, read against the "description". | pass if no "OWNER", "COLLABORATOR" or "MEMBER" comment in the thread states a culprit, a preferred approach, or a request, or if the description says how the pr follows it or why it does not. fail if such a comment exists and the description ignores it. | preferred |

## Verdict rule

Accept if every required check passes. Reject if any required check fails. The preferred check never changes the verdict. A check that does not apply passes. An unclear grade on a required check counts as fail, because a pull request that cannot be verified from the package is not ready to submit. When the verdict is reject, quote the evidence line of each failed required check in the summary.
