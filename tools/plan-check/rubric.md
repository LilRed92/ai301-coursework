# Rubric: is this plan ready to post and build from?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| cause fits repro | the plan's stated cause (its diagnosis or cause text), read against the "repro evidence" section: every numbered step, every artifact, every control run, and the actual line. | pass if each claim in the stated cause is consistent with every step, artifact and control run in the repro evidence, and the cause accounts for the actual behavior. fail if any step, artifact or control run rules the cause out (for example a control with the suspected component removed or bypassed still shows the bug, or the bad value is already present before the suspected step runs), if the cause is only borrowed from the issue or thread without the repro supporting it, or if the plan states no cause. | required |
| bounded scope | the plan's scope statement, its list of changes or approach, and its files. | pass if the plan describes one change that fixes the reproduced symptom (plus tests for it), and any other work is explicitly listed as out of scope. fail if the plan includes any work item the reproduced symptom does not need: refactors, migrations, rewrites, new options or settings, new frameworks, extra platforms, or other bugs. a strong core fix does not rescue a plan that bundles extras. | required |
| executable | the plan's named files, functions or modules, and its approach or ordered changes. | pass if the plan names the specific file, function or module it will change and states one chosen approach, so a stranger could start without asking the author. fail if the location is vague ("somewhere", "upstream or vendored, whichever is easier"), if the approach is an investigation with no chosen fix, if a core decision is deferred to build time, or if no file or area is named. | required |
| decisive test | the plan's test plan, read against the numbered steps in the "repro evidence" section. | pass if the test plan names specific steps or a command, taken from the repro, and an observable result that differs between the buggy and the fixed build (an output, exit code, value or visible change). fail if the only test is a generic suite run, a feeling ("should feel fast", "nothing else should break"), or a check that would pass with the bug still present. | required |
| maintainer direction | the "thread highlights" section, read against the plan comment and the plan's approach. | pass if the thread has no comment from an "OWNER", "COLLABORATOR" or "MEMBER" that states a culprit, a preferred approach, or a request (such as asking for testing), or if the plan comment names that direction and the plan follows it or says why it does not. fail if such a comment exists and the plan comment never engages it, or the plan does something different without saying so. opinions from "NONE" or "CONTRIBUTOR" authors do not count as direction. | required |
| ai disclosure | the contribution-policy line in the "repo facts" section, read against the plan comment text. | pass if the policy does not require disclosing ai use in comments or contributions generally (no ai policy, an assistive-use-allowed policy, a disclosure ask limited to pull requests, or a rule only about writing in your own words), or if the plan comment contains an explicit statement that ai was used and names the tool or extent. fail if the policy says all ai use must be disclosed and the comment has no such statement. | required |
| honest unknowns | the plan's risks and unknowns text, and the confidence of the stated cause. | pass if anything the repro does not show is labeled as an unknown or a risk instead of stated as fact. fail if the plan states an unverified guess as certain. | preferred |

## Verdict rule

Accept if every required check passes. Reject if any required check fails. Preferred checks never change the verdict. A check that does not apply (for example the thread has no maintainer comments) passes. An unclear grade on a required check counts as fail, because a plan that cannot be verified from the package is not ready to build from. When the verdict is reject, quote the evidence line of each failed required check in the summary.
